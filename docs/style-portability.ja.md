# 別の文書でも、選んだ画風を引き継ぐ

[README](../README.md) · [使い方](guide.ja.md) · [06の画風](../references/technical-spot.md)

同じSkillと「06」という名前を指定しても、細部の量、表示サイズ、画像生成へ渡す参照が変わると見え方は変わる。色、透明Alpha、PPTの構造検査だけでは、見本との一致を判定できない。

v0.3.6では、現在の生成用参照を配布Skillに同梱し、サイズに応じた細部の量を記録する。従来の双視点見本は視点の研究用として保つ。

## 小さな図の起点

![現在のコンパクト参照。明確な輪郭、大きな色面、少量の構造線](../assets/presets/technical-spot-compact.png)

72–128px程度なら `compact` を使う。主対象1つと必要な補助1つまでを基本とし、端子、配線、放熱フィン、螺子、複数の計測器を詰め込まない。必要な業務条件や構成要素は本文に残し、説明に大きな構造図が必要なら別図にする。

大きな絵を細かく描いてから縮めるのではなく、最終の図枠で主対象と構造が読めるか確かめる。24/32pxはさらに簡略化した記号にする。

## 題材と配色を変えた実生成

Skillの補助スクリプトが組み立てた依頼文と、同梱の参照画像を実際に内蔵imagegenへ渡した。新しい架空テーマを「署名する文書」「物資の識別」とし、ブルーからティールへ変更した。

![題材と配色を変更して生成した2点の透明図](examples/style-portability/transfer-result.png)

[ブリーフ](examples/style-portability/transfer-brief.json) · [styleLockと生成タスク](examples/style-portability/transfer-jobs.json) · [生成指示](examples/style-portability/transfer.prompt.txt) · [原図とAlphaの記録](examples/style-portability/transfer-record.json)

参照の対象や色をコピーせず、輪郭と細部の量を引き継いだ。作成Agentによる確認であり、独立した利用者評価ではない。2点を一枚に並べた透明の試作で、個別ファイルや同一画素の再現を保証するものではない。顧客文書、画面、ブランド、研究資料は使っていない。

## 引継ぎで残すもの

| 項目 | 内容 |
| --- | --- |
| Skill | 版とレシピID。古い研究用一覧の同じ番号を流用しない |
| 参照 | 現在の画像の相対パスとハッシュ。見てから生成ツールにも渡す |
| 図枠 | `iconSizePx` は実表示サイズ。出力PNGの解像度とは異なる |
| 細部 | `detailLevel` と主対象・必要な補助。小図の対象数を超えたら先に意味を整理し直す |
| 色 | 主色、輪郭、淡色などの役割。参照画像のブルーを固定しない |
| 確認 | 内容、画風、実際の小サイズ、Alpha、シリーズ内の統一を別々に確認する |

同じ名前のSkillを二つ検出させないため、バックアップはSkill検索対象フォルダーの外で保管する。更新後の依頼では現在の定義を読み、前の会話で使った番号や密度の解釈をそのまま引き継がない。
